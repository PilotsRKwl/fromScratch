## Review-sensitive rendering and filtering

Milestone 10.7 additions:

- [potion/RuneLitePotionSource.java](../src/main/java/com/fromscratch/potion/RuneLitePotionSource.java) reads `EnumID.POTIONSTORE_POTIONS` / `POTIONSTORE_UNFINISHED_POTIONS`, `VarbitID.MM_POTION_STORAGE_UNLOCKED`, native build/dose-change events and widget varp triggers. `client.runScript(ScriptID.POTIONSTORE_DOSES, enumId)` is the same read-only quantity query used by core Bank Tags in resolved RuneLite 1.13.3. It does not invoke deposit/withdraw scripts, menu actions, packet APIs or widget creation. Unavailable data is not empty; selected bottle size is not ownership.
- [potion/PotionEngine.java](../src/main/java/com/fromscratch/potion/PotionEngine.java), [PotionState.java](../src/main/java/com/fromscratch/potion/PotionState.java), [persistence/PotionCodec.java](../src/main/java/com/fromscratch/persistence/PotionCodec.java) extend the existing atomic bank checkpoint/audit, not a second saved ledger. Dose conversions/transfers use bounded same-session evidence; ambiguity requires explicit review. Format 10 reads existing format 9 without rewriting on load and retains older migration evidence. Backup import continues accepting format 9.
- [bank/Overdrafts.java](../src/main/java/com/fromscratch/bank/Overdrafts.java) derives debt increases only from newly committed physical changes and signed balances. [FromScratchPlugin.java](../src/main/java/com/fromscratch/FromScratchPlugin.java) uses local `ChatMessageManager` and RuneLite `Notifier`, without modal warnings or game input. [OutstandingPanel.java](../src/main/java/com/fromscratch/bank/OutstandingPanel.java) persists debt visibility independent of native slots/filtering. The separate sidebar storage list has been removed.
- [PotionSetupPanel.java](../src/main/java/com/fromscratch/bank/PotionSetupPanel.java) and [PotionCapture.java](../src/main/java/com/fromscratch/potion/PotionCapture.java) bind explicit setup consent to the same character, setup attempt and exact reviewed capture. Full enum queries include zero/offscreen types and must agree with a completed native five-child-row build. Dose-change alone cannot establish a baseline. Unavailable/dirty/stale data invalidates capture. An explicit not-unlocked attestation is retained in START evidence. Storage and full-bank baselines commit atomically before filtering.
- [PotionStorageOverlay.java](../src/main/java/com/fromscratch/overlay/PotionStorageOverlay.java) uses public widget bounds, `Widget.getFont().getTextWidth`, parent clipping and RuneLite Overlay/TooltipManager APIs. It only paints after the complete native bank interface. Physical labels, widgets, hitboxes, quantities and menus are untouched. Native font width and heart/row bounds limit placement; narrow rows show FS with exact units on hover. Zero is shown only for verified ownership; debt and unverified states use warning color. Lifecycle registration/removal is shared with the existing bank overlay.
- [BankCorrectionDialog.java](../src/main/java/com/fromscratch/bank/BankCorrectionDialog.java) adds a Potion Storage category to existing Manual Corrections. Normalized types use signed doses/items, cached physical stock is disclosed, revisions reject stale edits, and original snapshots remain immutable. Edits reuse `STORAGE_REVIEW` audit evidence and format 10; predecessor checkpoints yield before/after/deltas in paged manual history. Correction effects never enter the withdrawal-alert path or become a newly current observation session. Existing-run unresolved stock requires explicit recorded review.
- The bank overlay adds a supported `TooltipManager` hint for mixed stacks. No menu changes or new widget/geometry modifications are introduced. [PotionWealth.java](../src/main/java/com/fromscratch/potion/PotionWealth.java) uses existing cached guide prices to count bank/storage doses once. No new dependency, network endpoint, credential access or native integration is added to the plugin.

M9.2 uses public `Widget.getItemQuantityMode()` / `setItemQuantityMode(NEVER)` before drawing, then renders the original physical counter in **#A0A0A0 after the locked tint**. The original display modes restore on inactive/setup/closed/reset/disabled states and shutdown. Dragged items keep native counters. This is a **display flag**, not `setItemQuantity`, a new item/sprite, a mask over the sprite, geometry changes or an interaction change. It is deliberately disclosed rather than described as entirely draw-only. Public overlay/font utilities preserve clipping and compact native formatting. Final font/scaling compatibility still needs human visual review.

Dynamic Bank Tags owns its normal layout. Native-tab callbacks only filter/build the real bank; original physical stacks remain withdrawable. The title is presentation text, restored when inactive. No widget inventory is fabricated. Re-entrant operations update internal state before invoking native close/rebuild paths; membership callbacks perform set membership only. Client callbacks do not wait for Swing or disk. Full Bank remains available, and the initial snapshot always uses the complete item container.

No gameplay enforcement is present: **no withdrawal blocking/cancellation, conditional removal of gameplay menu choices, synthetic clicks/keys, server packet manipulation, actual ownership changes, deletion of real legacy items, passwords, or cloud synchronization**. Production `src/main` contains no reflection/JNI/native-memory calls, external process launch or custom classloader. Informational chat is added to the local chatbox, not sent as player chat. Manual correction/import/reset remain explicit player operations.

## Reset archive performance and current render repair

The native potion overlay uses "drawAfterInterface(InterfaceID.BANKMAIN)" in MANUAL mode. The installed core Bank code identifies item/text widgets at +1/+3 in five-child groups; core Bank Tags identifies +0 as a withdrawal control. Its bounds are not a full-row contract. Geometry now uses the sprite/name/quantity/heart union and observed column boundaries, never that control's bounds. Missing native font metrics have a conservative RuneLite-font fallback. Interface hooks, visibility, identity and committed projection gates are tested through the actual Overlay.render entry point. Up to six DEBUG status summaries are retained for pending live acceptance; they contain no holdings or identities. Accounting and setup observers are unchanged.

Reset still uses the existing background Filepath worker, CAS, forced archive/manifest/checkpoints and atomic current publication. Archive copies stream/hash source bytes once, force the destination, rewind the same handle for checksum readback, then publish the forced verified manifest. The redundant reopen/hash pass and per-byte String.format allocations are removed; old archive format/digest values remain identical. The controller publishes pending/reset-success states once, blocks duplicate intents while busy and only clears projections/caches after acknowledgment. No gameplay or account settings are changed.
